# SMS Gateway (Backend API & WebSocket Server)

Боевой production-ready бэкенд на **Python (FastAPI)** для отправки SMS и кодов верификации через подключенный Android-смартфон в качестве GSM-шлюза.

📱 **Android-клиент шлюза**: [https://github.com/yusuff84/sms-gateway-android](https://github.com/yusuff84/sms-gateway-android)

---

## 🏛 Архитектура системы

```
+---------------------+           REST API (X-API-Key / Bearer)
|   Внешний сервис    | --------------------------------------------> [ FastAPI Backend ]
| (авторизация/коды)  | <-------------------------------------------       |
+---------------------+        Webhook Callback (SENT/DELIVERED)          |
                                                                   WebSocket (Realtime)
                                                                   + Очередь & TTL Expiration
                                                                   + Ротация SIM 1 ⇄ SIM 2
                                                                           |
                                                                           v
                                                                [ Android GSM Gateway ]
                                                                - Foreground Service 24/7
                                                                - Material 3 Design
                                                                - SmsManager (SIM карты)
                                                                           |
                                                                           v
                                                                    [ Абонент / GSM ]
```

## 🛡 Возможности и защита от блокировок (Production-Ready)

1. **Защита баланса от списаний (Строго мобильные РФ `+79XXXXXXXXX`)**:
   - Автоматически блокирует международные номера (`+1...`, `+375...`, `+380...`).
   - Блокирует Казахстан (`+77...`, `+76...`).
   - Блокирует дорогие спецзоны с международным тарифом в коде +79: **Абхазию (`+7940...`)** и **Южную Осетию (`+7997...`, `+7998...`)**.
   - Блокирует городские стационарные телефоны (`+7495`, `+7812` и др.), не принимающие SMS.
   - Нормализует внутренний формат ввода с восьмерки: `8928...` ➔ `+7928...`.

2. **Умная балансировка между несколькими телефонами (Multi-Device Pool)**:
   - Если подключено 2 или более телефонов, сервер поровну распределяет нагрузку между ними (Round-Robin / Least-Idle).
   - Позволяет подключать несколько устройств для увеличения суточного лимита и отказоустойчивости.

3. **Антифрод-система, Spintax и визуальные латинские омоглифы**:
   - Защита от блокировки SIM-карт спам-фильтрами сотовых операторов (МТС, Мегафон, Билайн, Т2).
   - 25 встроенных разнообразных профессиональных шаблонов в базе данных.
   - Случайная подмена кириллических букв на визуально идентичные латинские (`B`, `a`, `o`, `p`, `c`, `e`, `y`, `x`). Текст выглядит абсолютно естественно, но полностью меняет байтовую сигнатуру для DPI.
   - Цифры OTP-кода не затрагиваются, автозаполнение на телефонах работает идеально.

3. **Идемпотентность (`idempotency_key`)**:
   - Предотвращение дублирования отправки SMS при повторных HTTP-запросах или сетевых сбоях.
   - Повторный запрос возвращает сохраненную задачу с флагом `is_duplicate: true`.

4. **Защита от флуда на один номер (Phone Cooldown)**:
   - Блокирует повторный запрос SMS на один и тот же номер чаще раза в 45 секунд.

5. **Контроль актуальности кодов (TTL / `expires_at`)**:
   - Очередь не доставляет устаревшие SMS-коды. Если телефон долго был вне сети, просроченные задачи автоматически переводятся в статус `EXPIRED`.

6. **Мгновенный статус 503 при выключенном телефоне**:
   - Если телефон не на связи, API сразу возвращает `503 Service Unavailable`, чтобы сайт мог предложить пользователю Telegram-авторизацию.

7. **Асинхронные Webhooks (`webhook_url`)**:
   - Отправка статусов (`SENT`, `DELIVERED`, `FAILED`) во внешнюю систему.
   - До 3 повторных попыток с экспоненциальной задержкой.

8. **Защита от перегрузки (Rate Limiting)**:
   - Встроенный лимитер `SlowAPI` (120 запросов в минуту на эндпоинт).

9. **Мониторинг и метрики (Prometheus)**:
   - Эндпоинт `/metrics` отдает счетчики `sms_processed_total{status="..."}` и датчик `sms_active_devices`.

10. **Миграции базы данных (Alembic)**:
   - Автоматическое накатывание миграций: `alembic upgrade head`.
   - Полная совместимость с SQLite и PostgreSQL.

11. **Современный веб-дашборд и выявление абузеров за 7 дней**:
   - Страница `/admin/abusers`: автоматический расчет всех номеров, запрашивавших коды за последние 7 дней и 24 часа.
   - Фильтрация по степени риска (`🚨 Критический абуз`, `⚠️ Подозрительный`, `🟡 Повторные запросы`, `🚫 Черный список`).
   - Быстрая блокировка/разблокировка в 1 клик.
   - При блокировке API сразу возвращает `403 Forbidden: номер находится в черном списке`.
   - Обновленный UI с типографикой `Inter`, темным сайдбаром, KPI-карточками и мягкими цветными бейджами.

12. **SQLAdmin Панель управления**:
   - Управление API-ключами клиентов.
   - Черный список номеров (`Черный список`).
   - Управление шаблонами антифрода (`SMS Шаблоны`).
   - Мониторинг устройств: статус сети, заряд аккумулятора, индикатор зарядки, время последнего пинга.
   - Детальный журнал сообщений с фильтрацией по статусам и слотам SIM.

## 🚀 Быстрый запуск

### Вариант 1: Запуск в Docker (1 команда)

```bash
docker compose up -d --build
```

Сервер автоматически применит миграции Alembic, создаст таблицы и запустится на порту `8000`.

* **Панель управления**: [http://localhost:8000/admin](http://localhost:8000/admin) (логин: `admin`, пароль: `admin123`)
* **OpenAPI Swagger**: [http://localhost:8000/docs](http://localhost:8000/docs)
* **Метрики Prometheus**: [http://localhost:8000/metrics](http://localhost:8000/metrics)
* **Healthcheck**: [http://localhost:8000/health](http://localhost:8000/health)

### Вариант 2: Запуск через Python virtualenv

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# Применение миграций
alembic upgrade head

# Запуск сервера
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# Запуск тестов
python test_backend.py
```

## 📡 Примеры использования API

### 1. Отправка проверочного кода с антифродом (самый надежный способ)

```bash
curl -X POST "http://localhost:8000/api/v1/sms/send" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: sms_ak_demo_master_token_12345" \
  -d '{
    "phone_number": "+79991234567",
    "code": "8412",
    "template_category": "auth",
    "idempotency_key": "auth_tx_998124_step1",
    "ttl_seconds": 300,
    "webhook_url": "https://myservice.com/api/webhooks/sms",
    "sim_slot": 0
  }'
```

**Ответ сервера:**
```json
{

  "phone_number": "+79991234567",

  "status": "SENDING",
  "created_at": "2026-09-14T01:24:44.620000Z",
  "expires_at": "2026-09-14T01:29:44.620000Z",
```

### 3. Контроль доступности телефона (HTTP 503)

Если телефон-шлюз сейчас выключен или не подключен к серверу, API мгновенно вернет ошибку `503 Service Unavailable`:

```json
{
  "detail": "SMS-шлюз сейчас недоступен: телефон для отправки SMS не в сети. Попробуйте позже или используйте альтернативный способ."
}
```

Ваш сайт может поймать эту ошибку и сразу предложить пользователю альтернативу (например, *«Получить код в Telegram»*), не заставляя его ждать несуществующего SMS.

*(Если вы хотите, чтобы SMS всё равно встало в очередь и дождалось включения телефона, передайте `"allow_queue": true`)*.
